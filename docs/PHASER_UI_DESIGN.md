# Phaser UI design: carved-stone expedition

Researched and implemented 2026-10-13 in response to the user's request for a modern mobile game interface drawn with Phaser Graphics. Gameplay rules and existing art are retained. This direction supersedes the visible HTML/CSS treatment in the earlier gameplay wireframes. The user approved the stone treatment and requested removal of the previous lapis theme. Stone is now the only implementation; there is no URL theme selector.

## Why this direction

The painted landscapes already supply color and detail. An equally busy HUD would compete with the island, while generic flat panels would feel disconnected from the miniature stone pieces. Warm limestone faces, dark basalt foundations, cut corners, broad chiseled bevels, recessed double keylines, and subtle mineral variation connect the two at mobile scale. Shallow seams and tooling cuts stay on the perimeter, with a quiet field behind each label. This is an interpretation of carved architectural stone rather than rough boulders or primitive tools. The controls feel like objects surrounding a tabletop without requiring per-button bitmap assets.

A honey-colored limestone primary action has a clear visual destination under the player's thumb. Ordinary turn completion uses dark green basalt to reduce its emphasis relative to rolling and committing a placement. The five resource cards form a recognizable hand; their thin material accents aid scanning while runtime labels preserve meaning. Player-colored seals and filled score pips make the race to the actual match target visible.

## Approved treatment and sizing refinement

The normal game URL always uses stone. The former comparison theme, its palette, conditional renderer paths, CSS overrides, and query selector have been removed. The material names now describe the stone roles directly.

The sizing pass keeps the approved visual design while correcting paragraph-leading inheritance in buttons, compact player-chip overflow, resource icons sized through transforms/negative margins, and texture-center text positioning. Controls use explicit line heights and consistent optical centering. Resource symbols have actual proportional layout dimensions. Player chips reserve space for both text rows and score pips, and their active crest stays within the strip. Detail rows and sheet headings wrap without squeezing the close button. The menu remains accessible when its contents are taller than the screen.

`semanticText.ts` measures the loaded Persian font bounds; `textGeometry.ts` aligns Phaser text to the browser baseline and reading edge, including mixed inline font sizes. Logical texture resolution avoids the installed Phaser 4 RTL renderer's backing-width offset on high-density displays. Long player/context labels ellipsize within their own measured region.

The stone material uses locally seeded, bounded Graphics marks, rather than image textures or the match random source. Large faces receive broad low-opacity mineral patches; pores, worn seams, and short tooling cuts remain near the rim. The latest board-priority sizing pass reduces raised edge depth to two pixels (one on press), keeps the foot inside the measured button, and limits the contact shadow to one pixel. Bevels are also thinner; flat cards/panels have no raised foot. Icon buttons show a 32-pixel face and a 20-pixel glyph centered in the retained 48-pixel touch target. With the all-player strip removed for single-player play, the HUD reserves 264 pixels normally and 260 in compact mode, leaving the rest to the board; exact resource counts sit above a shared icon/name row. Disabled controls are flatter and quieter while keeping their labels opaque. Selection uses dark bronze on limestone and warm gold on basalt; keyboard focus remains a separate outline.

Dark ink on limestone measures 6.27:1, body text on basalt 12.02:1, muted card text 4.72:1, and shortage text on stone 4.52:1 against the flat face colors. These calculations check the palette; the user still reviews the actual textured/rendered result on a device.

There is no constant shimmer, ambient bouncing, screen shake, fake currency, placeholder online feature, or newly invented rule. Graphics ornaments stay away from counts and labels. Light broad bevels remain visible at 1× mobile size.

## Rendering contract

The full-shell canvas renders backdrop → inset board → interface → temporary feedback in one Phaser game. CSS measures responsive semantic controls; Phaser draws their visible representation. This avoids duplicating text wrapping and hit regions while retaining a game-owned renderer. Transparent HTML is intentional infrastructure, not the visible design. It must remain in the accessibility tree and keep native modal behavior.

The renderer invalidates on semantic updates, resizing, scroll, focus, selection, and press changes. It excludes its own hidden RTL text canvases from observation. Stable Text/Image objects are reused and removed content releases textures/objects. Modal content is geometry-masked to its measured scrolling region. Motion does not translate the visible panel independently of its hit targets.

No asset was repainted or removed. The only art substitution is procedural dice, addressing the already documented RGB checkerboard and silhouette-clipping issue. Original source files and frame metadata remain available.

## Handoff

The user handles full game/device testing, production builds, and CI. Routine agent verification uses TypeScript, scoped lint/format checks, and focused Node layout tests. The session/layout tests protect confirmation, payment, Ahriman relocation, full tile IDs, the inset camera's coordinate transform, text baselines/reading edges, mixed font sizes, and constrained-label ellipsis. Visual composition, Persian line rendering, scrolling, and pointer/focus behavior still need the user's interactive device review; no browser was launched during implementation.
